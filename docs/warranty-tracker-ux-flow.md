# Wireframes וזרימת UX — WarrantyKeeper

**גרסה:** 1.0 | **תאריך:** ספטמבר 2026

מסמך זה מתאר בשלד טקסטואלי (wireframe) את המסכים המרכזיים ואת הזרימה בין הבין. המטרה: להעביר את המבנה והלוגיקה של כל מסך לפני השקעה בעיצוב UI מוקפד.

---

## מפת זרימה כללית (Flow Map)

```
Onboarding ──▶ Dashboard ──▶ מסך מוצר בודד ──▶ תביעת אחריות
     │              │
     │              ├──▶ הוספת מוצר (צילום קבלה)
     │              ├──▶ חיפוש / סינון
     │              └──▶ הגדרות (משק בית, התראות)
     │
     └──▶ הוספת מוצר ראשון (מיד אחרי הרשמה)
```

---

## מסך 1: Onboarding

```
┌───────────────────────────────┐
│                                │
│         [לוגו]                │
│                                │
│   "כל האחריות שלך, במקום      │
│    אחד. אף פעם לא תפספס       │
│    תיקון בחינם."               │
│                                │
│   [תמונת המחשה קצרה]           │
│                                │
│   ( כפתור: הבא )               │
│   ( כפתור קטן: יש לי חשבון )   │
│                                │
└───────────────────────────────┘
```
**לוגיקה:** 2-3 מסכי הסבר קצרים (סוויפ), ואז הרשמה (מייל/Google). מיד אחרי הרשמה — קפיצה ישירה למסך "הוסף מוצר ראשון", לא ל-Dashboard ריק.

## מסך 2: הוספת מוצר ראשון (Empty State מכוון)

```
┌───────────────────────────────┐
│  בוא נתחיל!                    │
│                                │
│  ┌──────────────────────────┐ │
│  │                          │ │
│  │     📷 צלם קבלה          │ │
│  │                          │ │
│  └──────────────────────────┘ │
│                                │
│  ( הזן ידנית במקום זאת )       │
│                                │
└───────────────────────────────┘
```
**לוגיקה:** הפעולה היחידה שמוצגת היא צילום — אין הסחות דעת. "הזן ידנית" זמין אך משני.

## מסך 3: אישור נתונים שזוהו (אחרי OCR)

```
┌───────────────────────────────┐
│  ← חזרה         מצאנו את זה:   │
│                                │
│  [תמונת קבלה קטנה]             │
│                                │
│  שם מוצר:   [מזגן טורנדו___]  │
│  קטגוריה:   [מזגנים ▾]        │
│  תאריך קנייה: [12.3.2026]     │
│  מחיר:       [3,200 ₪]        │
│  חדר:        [סלון ▾]         │
│                                │
│  אחריות עד: 12.3.2029 (משוער) │
│                                │
│   ( כפתור: שמור מוצר )         │
└───────────────────────────────┘
```
**לוגיקה:** כל שדה ניתן לעריכה inline. תאריך תפוגת האחריות מוצג כבר כאן כדי לחזק את הערך המיידי. אם הזיהוי לא ודאי — מוצגת תווית "משוער" עם אפשרות תיקון.

## מסך 4: Dashboard ראשי

```
┌───────────────────────────────┐
│  שלום, מיכל 👋       [🔍][⚙] │
│                                │
│  [הכל] [קרוב לתפוגה] [חדרים ▾]│
│                                │
│  🟢 מדיח כלים בוש              │
│      באחריות עד 2028           │
│  ─────────────────────────    │
│  🟠 טאבלט סמסונג               │
│      פג בעוד 12 יום            │
│  ─────────────────────────    │
│  🔴 אוזניות JBL                │
│      האחריות פגה               │
│  ─────────────────────────    │
│                                │
│           ( + )  [כפתור צף]    │
└───────────────────────────────┘
```
**לוגיקה:** מיון ברירת מחדל — הכי קרוב לתפוגה קודם. צבע = מצב סטטוס (ירוק/כתום/אדום). כפתור "+" צף תמיד נגיש להוספת מוצר חדש.

## עקרונות עיצוב מנחים (לשלב ה-UI המוקפד)

- **מקסימום 2 לחיצות** מ-Dashboard לכל פעולה מרכזית (הוספה, צפייה, תביעה).
- **צבע כשפה, לא כקישוט:** ירוק/כתום/אדום הם המידע העיקרי בסריקה מהירה של הרשימה — לא רק אסתטיקה.
- **טפסים קצרים ככל האפשר:** כל שדה לא הכרחי מוריד השלמת onboarding.
- **נגישות:** גודל טקסט וכפתורים מותאם גם למשתמשים מבוגרים (פרסונת "שרה" מה-PRD) — לא להסתמך רק על אייקונים בלי טקסט.
